Wolimons API Base URL: /api

Wolimons APIv1

Item values, RAP, trade ads and staff data for Wanwood. No key and no registration — every endpoint below answers a plain GET and sends CORS headers, so a browser on any domain can call it.

Item names, RAP and lowest prices come from Wanwood and are cached for ten minutes. Values, demand, trend and categories are set by hand on this site. The machine-readable index is at /api.

Items

Values and market data for tracked limiteds.

GET /api/v1/itemdetails Every tracked item

Description

Name, value, demand, trend, valuation method, categories, RAP and lowest ask for every item the site tracks. This is the one most tools want.

Value: an item nobody has valued is worth its RAP, so value is the figure the site shows — the hand-set one where there is one, Wanwood’s recent average price where there is not. valued says which of the two it is, and setValue is the raw stored figure (0 when nobody has set one).

Parameters

None.

Example response

  "success": true,
  "item_count": 42,
  "upstream": "wanwoo.xyz",
  "partial": false,
  "refreshedAt": 1755648000000,

      "lowestPrice": 11000,

Staff endpoints

These need a signed identity token from POST /api/identity and only work for accounts on the staff roster. Send it as Authorization: Bearer <token>.

POST /api/identity Get a token

Description

Proves you own a Wanwood account. Put the phrase in your Wanwood profile description first, then post it here.

Body

NameTypeDescription
userIdrequiredintegerYour Wanwood user id.
phraserequiredstringThe phrase currently in your profile description.

Example request

curl -X POST /api/identity \
  -H "Content-Type: application/json" \
  -d '{"userId": 1, "phrase": "zzz12345"}'

POST /api/vault/login Sign in and keep the session

Description

Signs in to Wanwood from the server and stores the session cookie it hands back. This exists for phones, which have no developer tools to copy a cookie out of. The password is used for that one request and is never stored, written to disk or logged — only the resulting cookie is kept. An account with a second factor cannot be signed in this way and is told to paste a cookie instead.

Body

NameTypeDescription
usernamerequiredstringThe Wanwood username.
passwordrequiredstringIts password. Used once, never kept.

Example response

{ "ok": true, "linked": true, "hint": "\u2026RET123",
  "account": { "id": 1, "name": "Nun" }, "balance": 1000 }
POST /api/vault/session Store a Wanwood session

Description

Hands the server a signed-in Wanwood cookie so it can buy on your behalf. Website owner only, and the vault password must ride along in x-vault-password. The cookie is verified against Wanwood before it is accepted, written owner-only to a file outside the served tree, and never returned by any endpoint — only its last six characters are ever echoed back. Send {"clear": true} to forget it.

Body

NameTypeDescription
cookiestringThe cookie header value from a signed-in Wanwood tab.
clearbooleanForget the stored session instead.

Example response

{ "ok": true, "linked": true, "hint": "\u2026RET123",
  "account": { "id": 1, "name": "Nun" }, "balance": 1000 }
POST /api/vault/buy Buy an item

Description

Buys one item using the stored session. This runs on the server on purpose: a browser will not attach Wanwood cookies to a request from another origin, so the same call from the page is blocked by CORS before it is sent. The price given is the price sent, so a listing that moved is refused upstream rather than costing more than was shown.

Body

NameTypeDescription
productIdrequiredintegerFrom the feed.
pricerequiredintegerThe expected price.
sellerIdintegerThe expected seller. Defaults to 1.
userAssetIdintegerFor buying a specific resale copy.

Example response

{ "ok": true, "bought": true, "status": 200, "reason": null, "balance": 750 }
POST /api/values/set Change an item value

Description

Sets value, demand, trend and categories for one item. Every edit is written to the change log.

Body

NameTypeDescription
idrequiredintegerThe item id.
valueintegerThe new value.
demandstringTerrible, Low, Normal, High or Amazing.
trendstringLowering, Unstable, Stable, Raising or Fluctuating.
categoriesarrayAny of rare, projected, hyped.

Rate limits are not enforced yet — please be gentle, every itemdetails refresh fans out over Wanwood.
