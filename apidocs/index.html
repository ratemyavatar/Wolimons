API Documentation

Wolimons serves a public JSON API for Wanwood limited-item values, players and trade ads - the same data the site itself runs on. There is no key and no registration: every endpoint below is a plain GET request, and every answer carries CORS headers, so a page on any domain may call it straight from the browser.
Item names, RAP and lowest prices are read from Wanwood and cached for ten minutes, so please poll no faster than you need to. Values, demand, trend and categories are set by hand on this site and update the moment they are saved. The machine-readable version of this page is served at /api.

Item details

GET/api/v1/itemdetails
Every item Wolimons tracks, keyed by item id: name, value, demand, trend, valuation method, categories, RAP and lowest ask. This is the one to build a value checker on.
GET /api/v1/itemdetails { "success": true, "item_count": 42, "partial": false, "items": { "61": { "name": "Perfectly Legitimate Business Hat", "value": 25000, "demand": "High", "trend": "Stable", "method": "rap", "categories": [], "rap": 24180, "lowestPrice": 26999, "updatedAt": 1787000000000, "updatedBy": "Nun" }, ... } }

Raw values

GET/api/v1/values
The raw value table this site runs on - only what the value team has set, with no Wanwood enrichment. Faster than itemdetails when you just need the numbers.
GET /api/v1/values { "success": true, "updatedAt": 1787000000000, "values": { "61": { "value": 25000, "demand": "High", "trend": "Stable", "categories": [], "method": "rap", "note": "" } } }

Value changes

GET/api/v1/valuechanges?limit=&since=
The change log behind the Value Changes page, newest first. limit caps the list (default 200), and since takes a millisecond timestamp for polling only what is new.
GET /api/v1/valuechanges?limit=50 { "success": true, "changes": [ { "id": 61, "field": "value", "old": 24000, "new": 25000, "by": "Nun", "at": 1787000000000 } ] }

Player info

GET/api/v1/playerinfo/<userId>
One Wanwood player by user id: their name, any staff rank they hold on Wolimons, and the badges that have been handed to them.
GET /api/v1/playerinfo/1 { "success": true, "id": 1, "name": "Nun", "role": "owner", "roleLabel": "Site Owner", "badges": ["certified-wanwoodian"] }

Recent trade ads

GET/api/v1/getrecentads?limit=
The trade ad board, newest first. Each side of an ad is up to four slots; a slot is either an item or one of the request tags like rap or wishlist.
GET /api/v1/getrecentads?limit=25 { "success": true, "ads": [ { "id": "9-1787000000001", "creatorId": 9, "creatorName": "Someone", "createdAt": 1787000000001, "offer": [ { "kind": "item", "id": 61, "name": "..." }, null, null, null ], "request": [ { "kind": "tag", "slug": "rap" }, null, null, null ] } ] }

Staff roster

GET/api/v1/roles
Who ranks what on Wolimons - Site Owner, Value Manager and Value Team.
GET /api/v1/roles { "success": true, "roles": [ { "name": "Nun", "role": "owner", "grantedBy": "Nun" } ] }

Granted badges

GET/api/v1/badges?name=
The badges handed out by the site. With no parameters it returns every grant plus the list of badge ids that can be granted; with ?name=X it returns just that player's badges.
GET /api/v1/badges?name=Nun { "success": true, "name": "Nun", "badges": ["certified-wanwoodian"] }

Notes

All endpoints answer application/json. On an error the status code says what happened and the body carries a success: false with a human message:
{ "success": false, "error": "Wanwood could not be reached, or there is no such player." }
